ORION uses API keys and session cookies for authentication. All endpoints are freely accessible — there are no premium tiers, subscription checks, or feature gating.

---

## Auth Stack

| Layer | Technology | Purpose |
|-------|-----------|---------|
| Browser session | `ors_` HttpOnly cookie | Short-lived session token for dashboard reads |
| API key | `X-ORION-Key` header | Server-to-server, scripts, SDKs |
| OAuth bearer | `Authorization: Bearer <token>` | MCP clients |

### Key Files

| File | Purpose |
|------|---------|
| `src/services/auth-state.ts` | Reactive auth state and session hydration |
| `server/auth-session.ts` | Server-side session validation |

---

## Server-Side Session Enforcement

The Vercel API gateway accepts API keys and session cookies for endpoint access:

1. **Static API key** — `X-ORION-Key` header (existing flow, unchanged)
2. **Browser session** — `orion-session` HttpOnly cookie for dashboard reads

The gateway tries the API key first. If that fails, it falls back to the browser session cookie. Non-session endpoints don't require any authentication from web origins.
